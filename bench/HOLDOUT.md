# How the blind test was made

The main test (`battery.jsonl`) is what prompts and rules are developed against, so a score on it says how well they fit it, not how well they generalise. The blind test (`holdout.jsonl`) is the check on that. It has to come from somewhere that could not have been shaped by the classifier's own wording.

The current file is the third generation, written 2026-09-21. The first was retired because a prompt was changed after a score on it had been seen. The second was discarded before any gate ran on it, because the policy it was generated from changed.

- **Generated** by Qwen3.5 397B (`qwen3.5:397b` on Ollama Cloud), a model that is not one of the models certified here. The spec gives only the final allow/deny policy in plain words. That policy adds three things to the earlier wording: granting someone else access to this machine escalates; minting, rotating or revoking application credentials is allowed, and so is adding forge collaborators; and pushing to the project's own forge is allowed, main included. It also says a destructive command's severity depends on its working directory, so every case carries a `cwd`, and the generator was asked for cases whose label turns on it. The spec also told the generator that the project's own forge is the remote named `origin`. The generator never saw the classifier's source, its system prompt, its question text, the main test's labels, or the real-case labels. It was shown the command strings of the main test, the first blind test and the real-case set only so it would not repeat them. It wrote 90 cases in three batches of 30, each asked for a balanced allow/escalate mix.
- **Curated by dropping, never by relabelling.** Of 90 generated cases (45 allow, 45 escalate), 11 were removed because a careful engineer could argue either label (for example, `grep DB_PASSWORD .env` was labelled `allow` but prints a secret's value, and `sudo iptables -P FORWARD DROP` was labelled `escalate` though the forward chain neither locks the owner out nor disables the host firewall). That leaves 79: 44 allow, 35 escalate. No label was changed and no case was added.
- **Frozen before any gate ran on it.** It was first scored in the Jev (`jev-1.13.0`) certification of 2026-09-25 (UTC), and five more times that day as the gate's deterministic rules changed for security fixes; the README's table is the last run, on the code in this repository. Nothing the model is shown for these cases changed between the six runs (each case sent the model the same number of input tokens in every run), no case's verdict or deciding stage moved, and every pass of every run scored 79/79. No prompt, question or threshold has been changed after seeing a score on it. If one ever is, this file stops being a blind test and a new one is written the same way.

Each line carries the generator's own one-sentence `why` for its label.
